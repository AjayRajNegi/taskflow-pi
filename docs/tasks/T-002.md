# Task T-002: Database schema: tenants and users tables

## Goal
Define and apply the initial database schema for the tenants and users tables as per the data model, including necessary constraints, indexes, and UUID extension.

## Requirements Covered
- From data model: Tenants and tables definitions, primary keys, foreign keys, constraints.
- From architecture: Use PostgreSQL + Prisma as the ORM.
- From system components: Prisma ORM responsibility includes schema management and migrations.

## Acceptance Criteria

- Prisma schema (`prisma/schema.prisma`) defines `Tenant` and `User` models with:
  - UUID primary keys (default `uuid_generate_v4()`).
  - Required fields: `tenants.name`, `users.tenant_id`, `users.email`, `users.password_hash`.
  - Unique constraint on `users.email`.
  - Foreign key from `users.tenant_id` to `tenants.id` with ON DELETE RESTRICT.
  - Timestamps `created_at` and `updated_at` with default `now()`.
  - Indexes as per data model (implicitly created by Prisma for foreign keys and unique fields).
- Migration is generated and applied successfully (`prisma migrate dev`).
- Database connection is configured via environment variable `DATABASE_URL`.

## Files/Modules Likely to be Touched
- `prisma/schema.prisma`
- `prisma/migrations/` (new migration folder)
- `src/shared/tenancy/` (tenant context helpers, if any)


## Out of Scope
- Tasks, attachments, subscriptions tables (covered in later tasks).
- Row-Level Security (RLS) implementation (open question, may be considered later).
- Indexes beyond those implicitly created by Prisma (explicit indexes only if needed for query performance beyond FK and unique).
- Soft deletes (`deleted_at` columns) – not required per requirements.

## Important Implementation Notes
- Prisma is already installed and is configured properly.
- Follow the data model exactly for the tenants and users tables.
- Use Prisma's `@default(uuid())` or `@db.Uuid` with `@default(raw("uuid_generate_v4()"))` depending on Prisma version and PostgreSQL extension.
- Ensure the `uuid-ossp` extension is enabled in the migration (Prisma may handle this via `extension()` in schema).
- Passwords will be hashed in the service layer; the schema only stores the hash.
- Consider adding a `status` or `is_active` field to users as per data model (default true).
