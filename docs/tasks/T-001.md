# Task T-001: Project setup and health check endpoint

## Goal
Set up the project structure, configure the development environment, and implement a minimal health check endpoint to verify the application is running.

## Requirements Covered
- From project requirements: Need to build a production-oriented REST API.
- From architecture: Application should be runnable locally without requiring paid infrastructure.
- From system components: HTTP layer responsibility includes health check endpoints.

## Acceptance Criteria
- Project can be cloned and built with `bun install` (or equivalent).
- Application starts successfully on a local port (e.g., 3000).
- GET request to `/health` returns 200 OK with JSON body: `{ "status": "ok", "timestamp": "<ISO 8601>", "version": "1.0.0" }`.
- Basic unit test framework (Vitest) is configured and a placeholder test passes.
- Dockerfile (optional) or deployment notes exist for staging deployment.
- No database connection is required for the health check (it should work even if DB is down, but we may add DB connectivity check later).

## Files/Modules Likely to be Touched
- `src/server.ts` or equivalent entry point
- `src/app/routes/health.ts` (or similar)
- `package.json` (or `bunfig.toml`) for dependencies and scripts
- `tsconfig.json` for TypeScript configuration
- Vitest configuration (`vitest.config.ts`)
- Basic `.gitignore`, `README.md` (if not existing)

## Tests to Add or Update
- Add a unit test for the health check route handler (if separated).
- Add an integration test that starts the server and calls `/health`.
- Ensure the test suite runs and passes.

## Dependencies
- None (this is the first task)

## Out of Scope
- Database setup and connections (covered in T-002)
- Authentication, authorization, business logic
- OpenAPI specification generation (covered later)
- Background job infrastructure
- File storage setup
- Payment provider integration

## Important Implementation Notes
- Use Bun as the runtime as per architecture decision.
- Choose a minimal HTTP framework compatible with Bun (e.g., Elysia, Hono, or Barely) – but note the architecture says "TypeScript/Bun-compatible HTTP framework". We'll assume the team will choose one; for the plan, we note that the health check should be implementable with any framework.
- The health check should not depend on external services to avoid false negatives; however, a stretch goal could be to include optional DB connectivity check (but not required for acceptance).
- Keep the project structure aligned with the recommended architecture: `src/modules/`, `src/infrastructure/`, `src/shared/`, `src/app/`.
- Ensure the application uses strict TypeScript mode.
- Set up linting (ESLint) and prettier if not already present.
