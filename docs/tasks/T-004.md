# Task T-004: Tenant service and API: create tenant, get user's tenant

## Goal
Implement tenant management functionality: creating a tenant and retrieving the authenticated user's tenant.

## Requirements Covered
- From project requirements: Multi-tenancy, users must belong to a tenant.
- From API contracts: `/tenants` (POST), `/users/me/tenant` (GET).
- From security model: Authorization model (tenant-based), tenant-isolation model.
- From system components: Tenant service responsibility; HTTP layer handles routing and authorization.

## Acceptance Criteria
- POST `/tenants` (protected):
  - Requires valid JWT.
  - Accepts JSON with `name`.
  - Creates a tenant record.
  - Returns 201 with tenant info (id, name, timestamps).
  - Returns 400 if name missing.
  - Note: Permissions for tenant creation are an open question; for now, any authenticated user can create a tenant (to be refined later).
- GET `/users/me/tenant` (protected):
  - Requires valid JWT.
  - Returns the tenant associated with the authenticated user (from user's tenant_id).
  - Returns 200 with tenant info.
  - Returns 404 if user has no tenant (should not happen if data integrity maintained).
- Tenant service methods:
  - `createTenant(data)`: validates input, creates tenant.
  - `getUserTenant(userId)`: retrieves tenant for a given user.
- Unit and integration tests cover:
  - Successful tenant creation.
  - Retrieving user's tenant.
  - Validation errors.
  - Unauthorized access (no token).
  - Ensuring that a user can only see their own tenant (via `/users/me/tenant`).

## Important Implementation Notes
- The create tenant endpoint does not automatically add the requesting user to the tenant. Users must be added via registration (which specifies tenantId) or via an "add user to tenant" endpoint (to be implemented later, possibly in T-005 or a separate task).
- The get user's tenant endpoint simply returns the tenant from the user's record.
- Ensure that tenant creation validates the name (non-empty, reasonable length).
- Consider adding a unique constraint on tenant name? Not required; duplicate names allowed.
- Timestamps should be managed by Prisma (`updatedAt` on update).
- For testing, use the authentication helper to get a token for a registered user.
